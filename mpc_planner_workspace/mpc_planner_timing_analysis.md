# mpc_planner 연산 시간·주행 진단 통합 분석 — A·D · 3대/4대

> 문서 구성: 1~7절은 기존 3대의 2초·4초·6초 분석이며, 8절은 사용자 제공 4대 로그의 추가 분석이다.

> 최신 추가 측정은 4초 예측이다. 예측 길이별 원본 수치와 실행 조건을 구분해 한 파일에 모았다. 현재 Gazebo 실행 설정은 N=30, dt=0.2초, 예측 시간 6초다(2026-11-04 설정 변경). 기존 측정값은 각 실험 당시 조건이며 이번 변경으로 새 시험을 실행한 것은 아니다.

## 1. 분석 대상과 핵심 판단

**4초 예측에서 solver 가중 평균 39.11ms, 전체 planning 가중 평균 53.29ms였다. 100ms 초과는 5/799회(0.63%)로, 2초·기존 6초의 0회와 달리 일부 지연이 관측됐다. 자동 시험은 위치·속도·간격 조건으로 통과했지만 종료 시 세 로봇 모두 방향 정렬 중이었다.**

2초·4초는 시나리오 A·로봇 3대의 새 초기 상태에서 각각 한 번 직접 실행했다. 두 플래너를 동시에 주행하지 않고 MPC 다음 DMPC 순서로 측정했다. GUI는 띄우지 않았으며 기존 MPC 웹 뷰어는 두 측정 동안 일시 정지했다가 복구했다. 기존 6초는 앞선 실행의 기록으로, 새로 재시험하지 않았다.

| 항목 | 조건 |
|---|---|
| 시나리오 / 로봇 | A / robot_a·robot_b·robot_c |
| 시작점 → 목적지 | A (-3,0)→(3,0), B (3,0)→(-3,0), C (-6,0)→(6,0) |
| A 환경 | 정적 장애물·좁은 복도 경계 없음 |
| 예측 단계 | 2초: 10단계 / 4초: 20단계 / 6초: 30단계 |
| 예측 간격 / 모델 | 0.2초 / CV+Gaussian, noise 0.3, risk 0.05 |
| 운동 한계 | 속도 1.5m/s, 가속도 ±0.7m/s², 각속도 ±0.8rad/s |
| 목표 재계획 / 주행 명령 | 10Hz / 20Hz |
| 새 시험 제한 | 각 최대 120초, 공통 통과 조건 충족 시 조기 종료 |
| MPC solver | acados + HPIPM, 바깥 반복 설정 10 / QP 최대 150회 |
| DMPC solver | CasADi + IPOPT, adaptive barrier / 최대 150회 / 0.25초 예산 |

예측 단계 이외의 cost 가중치·기존 제약 구조·운동 한계·solver 설정은 이 비교를 위해 추가 튜닝하지 않았다. 명목 예측 시간은 N×dt이며, 두 구현의 단계별 제약 적용·경로 발행 방식 차이는 유지했다. MPC는 각 실행의 생성 solver 단계 수를 확인한 뒤 빌드했다.

**6초 기록의 제한:** 사용자 제공 timing 원문에는 N·시나리오·전체 시험 시간·GUI 부하가 직접 들어 있지 않다. 앞선 실행 문맥의 6초 기록으로 분류했지만, 새 2초·4초와 완전히 통제된 조건의 데이터라고 보지는 않는다. 새 2초·4초는 실행 JSON과 설정 보존 파일로 A·3대·N을 확인했다.

### 전체 표본 수로 가중한 요약

| 예측 | 총 계산 | solver 가중 평균 | planning 가중 평균 | planning 최대 | 100ms 초과 | 계획 채택 |

| 4초 | 799 | **39.11ms** | **53.29ms** | 315.8ms | 5/799 (0.63%) | 789/799 (98.75%) |
| 6초 | 866 | **30.64ms** | **41.03ms** | 99.1ms | 0/866 (0.00%) | 863/866 (99.65%) |

가중 평균은 `Σ(로봇별 평균 × 계산 수) / 전체 계산 수`다. 표는 소수 첫째 또는 둘째 자리로 표시했다. MPC JSON은 소수 셋째 자리, 기존 MPC 6초 원문은 소수 첫째 자리 평균이므로 합산값도 해당 반올림의 영향을 받는다.

solver 시간은 **한 재계획에서 실행한 solver API 호출 시간의 합계**다. 호출당 평균이 아니며, 여러 후보를 풀면 합산한다. planning은 입력 처리·예측·초기 추정·solver·검증·결과 발행을 포함한다. 시뮬레이션 시계가 아닌 monotonic/steady-clock 경과 시간을 쓴다.

실패한 solver 호출과 버린 계획도 계산 표본에 포함하지만 solver를 호출하지 않는 대기·도착 tick은 제외한다. accepted는 실행 가능한 계획 또는 검증된 fallback 발행 횟수로 내부 QP/IPOPT 성공률·도착률과 다르다. 세 로봇은 동시 계산하므로 합산 평균을 전체 시스템 한 주기의 시간이나 CPU 사용률로 해석하지 않는다.

## 3. 연산 시간 변화와 후보 탐색

2초 마지막 측정은 세 로봇 모두 attempts=5였고, 4초는 A·B가 5, C가 1이었다. 기존 6초의 마지막 측정은 A가 5, B·C가 1이었다. 이 값은 마지막 재계획의 호출 수이며 전체 평균 후보 수는 아니다.

4초에서 A·B의 solver 누적 평균은 52.0ms·45.3ms로 C의 20.0ms보다 컸다. 여러 후보 탐색·실패 후 재시도는 재계획당 solver 합계를 늘린다. 후보별 성공·검증 결과와 비용을 분리 기록하지 않아 마지막 5개 호출이 모두 성공했는지는 확정할 수 없다.

기존 6초 A는 첫 관측의 planning 평균 22.6ms에서 최종 77.3ms로 상승했고 여러 출력에서 4~5회 호출이 관찰됐다. 2초·4초·6초 결과가 단순히 예측 단계 수에 비례하지 않는 이유를 볼 때 이러한 탐색 정책·복구 빈도와 주행 상황을 함께 고려해야 한다.

계획 미채택은 2초 95회(A 94·B 1·C 0), 4초 10회(A 6·B 3·C 1), 기존 6초 3회(A 2·B 0·C 1)였다. 따라서 이번 2초의 평균 계산이 가장 짧았다고 해서 계획 채택률도 가장 좋았던 것은 아니다. 미채택을 충돌 또는 내부 QP 실패와 일대일로 대응하지 않는다.

예측 시간을 줄이면 변수·제약 수만 감소하는 것이 아니다. 미래 충돌을 보는 범위, 누적 stage cost 항 수와 terminal cost의 상대적 영향, 초기 추정·후보 선택도 달라질 수 있다. 따라서 계산 시간이나 주행 결과가 예측 길이에 정확히 비례할 것을 기대하면 안 된다. 관측 지연이 없을 때 예측 끝의 Gaussian 추가 반경은 약 0.46m(2초), 0.66m(4초), 0.80m(6초)이며 같은 시점의 확률 모델은 유지했다.

| 예측 | 로봇 A | 로봇 B | 로봇 C | 전체 표본 가중 차이 |
|---|---:|---:|---:|---:|
| 2초 | 12.2ms | 8.9ms | 11.4ms | **10.77ms** |
| 4초 | 17.1ms | 18.2ms | 7.2ms | **14.17ms** |
| 6초 | 19.2ms | 5.5ms | 5.4ms | **10.39ms** |

위 값은 같은 누적 표본 집합의 planning 평균에서 solver 평균을 뺀 것이다. 입력·예측·후보 준비·파라미터 설정·독립 경로 검증·선택·발행 등을 포함한다. 최댓값끼리 빼서 최대 오버헤드로 해석하지 않는다.

4초에서 solver 합계의 관측 최대는 78.0ms였지만 planning 최대는 315.8ms였다. solver 외 처리와 OS 스케줄링 지연 등도 전체 지연에 영향을 줄 수 있음을 보여준다. 다만 단계별 계측이 없으므로 특정 처리의 원인으로 확정하지 않는다. 두 최대가 같은 표본이라고 가정하여 차이를 정확한 최대 오버헤드로 계산하지도 않았다.

## 6. waiting·stale와 기록 해석

모니터가 플래너보다 먼저 시작하면 no timing publisher 또는 waiting_for_fresh_states가 먼저 나올 수 있다. 이후 정상 측정값을 받았다면 이 시작 메시지만으로 계측 실패라고 해석하지 않는다.

모니터의 stale는 기본 설정에서 약 4초 넘게 새 timing 메시지를 못 받았다는 뜻이다. odom 자체의 신선도나 목적지 도착 여부를 뜻하지 않는다. solver를 호출하지 않는 도착 상태에서는 새 통계가 없고, 프로세스 종료·입력 대기·통신 문제로도 갱신이 멈출 수 있다. 마지막 timing outcome과 최종 planner 상태는 서로 다른 시점의 기록이다.

2초 간격의 화면 출력은 모든 재계획의 원시 표본이 아니다. 반복된 누적 횟수는 새 계산으로 세지 않았고, 직접 시험의 최종 통계는 JSON을 우선했다. 예를 들어 DMPC 2초 A의 마지막 timing은 solver_failed였지만 최종 상태는 goal_reached였다. 개별 후보·QP 반복·실패 원인별 통계나 p95 같은 분포 통계는 이 자료만으로 계산할 수 없다.

4초 시험용 sim·test·monitor는 종료했고 측정 동안 일시 정지한 기존 MPC 뷰어는 복구했다. 새 보고서를 만들기 위해 추가 주행 튜닝이나 6초 재시험을 수행하지 않았다.

## 7. MPC·DMPC 비교와 한계

현재 비교에서 DMPC의 관측 solver 평균은 더 길었지만, 이 비율을 IPOPT 자체의 보편적인 성능 비율로 해석하지 않는다. 두 구현은 cost·제약 샘플링·초기 추정·후보 수·검증·비동기 처리 방식과 설정상 계산 예산이 다르다.

- 2초·4초는 같은 A·3대·headless·최대 120초 조건으로 각각 한 번 실행했다. 반복 시험의 분산·신뢰구간을 평가하지 않았으며 실행 순서는 MPC 다음 DMPC였다.
- 조기 종료 시점과 로봇별 활성 구간이 달라 전체 평균의 표본 구성도 다르다. 특히 DMPC 4초는 C의 표본 비중이 크다.
- 기존 6초는 이력 참고값이다. MPC 6초 원문에는 시나리오·GUI 부하·전체 시험 시간 메타데이터가 없고, 같은 주행 상황을 재현한 통제 실험이 아니다.
- 명목 예측 시간을 바꾸면 계산 규모뿐 아니라 계획 행동·회피 범위·목표 비용의 상대적 영향도 변한다. 주행 시간을 solver 성능 차이만으로 설명하지 않는다.
- 엄격한 도착 성능을 비교하려면 공통 위치·속도 조건 외에 방향·각속도 조건까지 맞춘 별도 시험이 필요하다. 이번 계측을 위해 그 조건을 바꾸지는 않았다.

평균 계산 시간만으로 예측 길이나 플래너의 우열을 정하지 않고, 주기 초과·계획 채택·간격·도착 조건을 함께 평가해야 한다.
